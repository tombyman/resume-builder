# Resume Builder — адаптация IT-резюме под рынок РФ

## Входные данные

1. **Существующее резюме** — обязательно: путь к файлу (`.md`, `.txt`, `.pdf`; текст PDF извлекай через `pdftotext -layout <файл> -`) или текст в сообщении.
2. **Вакансия** — опционально: текст вакансии или её требования, под которые адаптируем.

Если резюме не предоставлено — попроси его одним сообщением и ничего не выдумывай.

Результаты (RU/EN `.md` и PDF) создавай в рабочем каталоге, если пользователь не указал иное место.

## Процесс

1. Прочитай `references/russian-it-market.md` — стандарты российского рынка и структура резюме.
2. Проанализируй резюме: целевая должность, уровень (junior/middle/senior/lead), стек, пробелы (даты, метрики, контакты).
3. Задай **один** сводный список вопросов по недостающим данным: контакты (включая Telegram `https://t.me/username` и ссылки на портфолио/GitHub), даты, образование; включать ли профессиональное фото — если в исходном резюме есть строка вида `Фото: <путь к локальному файлу>`, спроси, включить его в RU-версию, EN-версию или обе; если фото нет — не добавляй и путь не выдумывай; если релевантно стеку — реальный опыт работы с AI/LLM-инструментами. Зарплатные ожидания по умолчанию **не спрашивай и не включай** в резюме: их обсуждают при первом контакте, а на hh.ru указывают в отдельном поле. Пропуски вымышленными значениями не заполняй.
4. Если предоставлена вакансия: выпиши ключевые слова и требования; перестрой акценты резюме под них — порядок навыков, формулировки должностей. Опыт и навыки, которых нет в источниках, **не добавляй**. Сгенерируй сопроводительное письмо (структура — в references): `YYYY-MM-DD Фамилия Имя - сопроводительное письмо.md` (только Markdown — текст для вставки в отклик; EN-вариант, если пользователь работает и с англоязычными откликами).
5. Сгенерируй RU-версию: `YYYY-MM-DD <Фамилия Имя> - резюме ru.md` (дата — день создания; структура — из references).
6. Сгенерируй EN-версию: `YYYY-MM-DD <Lastname Firstname> - resume en.md`. Это не дословный перевод, а переработка под англоязычные conventions (см. references).
7. Если пользователь подтвердил фото: скопируй файл из пути в строке `Фото:` исходного резюме рядом с генерируемыми `.md`-файлами (например, `photo.jpg`) и вставь в начало раздела «Контакты», первой строкой, **до** ФИО, raw-LaTeX-блоком — так фото оказывается справа вверху (атрибут `align` у картинок pandoc в LaTeX-выводе игнорирует):

   ````markdown
   ```{=latex}
   \noindent\hfill\includegraphics[width=2.8cm]{photo.jpg}
   ```
   ````

   В команду сборки PDF добавь `-V graphics=true` — иначе пакет `graphicx` не подтянется (pandoc включает его автоматически только для «нативных» картинок, а здесь `\includegraphics` лежит в raw-блоке).
8. Собери PDF для каждой версии (команды ниже).
9. Покажи пользователю результат (RU/EN `.md` + PDF и сопроводительное письмо, если была вакансия) и краткий список изменений; спроси, что доработать.

## Правила стиля

- Конкретные факты вместо общих фраз: «автоматизация процессов» → «конвейеры CI/CD на GitLab для проектов на Python и Go».
- Достижения — по формуле «достиг X, который измеряется в Y, сделав Z»: числа, сроки, масштаб («на 30%», «12 сервисов», «команда из 5 человек»).
- Желаемая должность — без грейда (junior/middle/senior); зарплатные ожидания в резюме не включать, если пользователь явно не попросил.
- Названия технологий — как в исходном резюме (kubernetes, ansible), без «красивых» заглавных.
- Опыт — в обратном хронологическом порядке; у каждой позиции блок «Достижения», если есть что указать, и **рассчитанная длительность** (RU: «3 года 4 месяца» — у всех позиций; EN: `2 yrs 6 mos` — только для текущего места) по датам начала и конца из резюме; для текущего места («по настоящее время» / `Present`) — до сегодняшнего дня. Если в исходном резюме нет дат — уточняй их в сводном списке вопросов, не выдумывай.
- Из исходного резюме ничего не удаляй без причины: при сокращении объясни пользователю, что вырезано и почему.

## Сборка PDF (локально)

По умолчанию pandoc берёт шрифт Latin Modern, в котором **нет кириллицы** — mainfont обязателен. Шаблон вёрстки резюме лежит рядом со скилом: `${CLAUDE_SKILL_DIR}/templates/resume.latex` (путь подставляется Claude Code при запуске):

```bash
pandoc "YYYY-MM-DD Фамилия Имя - резюме ru.md" --pdf-engine=xelatex \
  --template=${CLAUDE_SKILL_DIR}/templates/resume.latex \
  -V mainfont="DejaVu Serif" -V sansfont="DejaVu Sans" \
  -V fontsize=11pt -V geometry:margin=1.8cm \
  -o "YYYY-MM-DD Фамилия Имя - резюме ru.pdf"
```

`--metadata title` не передавать — заголовок документа создаёт сам контент резюме (раздел «Контакты»). Аналогично для EN-версии. Если в `.md` есть фото (шаг 7), добавь `-V graphics=true`; файл картинки должен лежать рядом с исходным `.md`. Внешние сервисы конвертации не использовать. Если xelatex недоступен — обход через `pandoc → HTML → chromium --headless --print-to-pdf`.
